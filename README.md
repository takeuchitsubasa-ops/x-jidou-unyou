# X自動運用（x-jidou-unyou）

AI で毎日 X に投稿している人向けの仕組みです。いまの「毎日3本のスレッドを自動で出す」形はそのままに、次の4つを足します。GitHub の中だけで動き、自分のパソコンは要りません。

1. **テーマを1行書くだけで、自分の書き方のスレッドになります。** 自分のアカウントで伸びたスレッドの全文（`メモリ/お手本.md`）をお手本にして、つかみ・本文・締めの形も、長さも、言い回しも合わせて書きます。テーマはスマホから Issue で足せます。毎回同じ形に見えないよう、言い出しは自分が使った言い出しの中から直近と重ならない物を選び、1日の3本は話の種類も分けます
2. **伸びる型とお手本を、毎週、自分の数字で入れ替えます。** 日曜の夜に投稿ごとの表示数を見て、伸びた書き出しを次の週の書き方に反映し、もっと伸びたスレッドがあれば、お手本と入れ替えます。その週に使った言い出しも、言い出しの候補に足します
3. **出どころの無い数字・体験談は、投稿しません。** 使う事実は、あなたが `メモリ/` に書いた「会社の事実」と「ネタ帳」だけです。確かめられなかった案は「確認待ち」で止まり、あなたが OK を付けた物だけ出ます（数字も体験談も使わない一般的な説明は、確かめの対象外です）
4. **現場の話を、スマホから足せます。** GitHub のアプリで Issue に一言書いてラベル「ネタ」を付けると、翌朝ネタ帳に入ります

投稿は朝6時・昼12時・夕方18時に、1スレッド（3投稿）ずつです。最初の試し運転は Claude の鍵だけで始められ、投稿はしません。

## 使う言葉

<details>
<summary>リポジトリ・Workflow・Secrets などの意味（開く）</summary>

- **リポジトリ**：この仕組みのファイル一式を置く、GitHub 上のフォルダです
- **Workflow（ワークフロー）**：GitHub が、決めた時刻に自動で動かす作業の手順です。`.github/workflows/` に4つ入っています
- **Secrets（シークレット）**：X や Claude の「鍵」（パスワードのような文字列）を、GitHub に預けておく設定です。預けた鍵は、画面でもう一度見られません
- **Artifacts（アーティファクト）**：Workflow が終わったあとに、ダウンロードできる結果のファイルです
- **Issue（イシュー）**：GitHub の「メモ・連絡」の機能です。この仕組みは、現場の話の入力と、確認待ちの連絡に使います
</details>

## 最初にやること（Claude の鍵だけで始められます）

最初の試し運転に必要なのは、**Claude（Anthropic）の API キーだけ**です。X の鍵は、あとでかまいません。投稿はしません。

1. 右上の「Use this template」→「Create a new repository」で、自分のリポジトリを作ります（公開範囲は「Private」）
2. https://console.anthropic.com で API キーを作ります
3. リポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」で、名前 `ANTHROPIC_API_KEY`、中身にキーを入れます
4. 「Actions」タブ →「4 試し運転」→「Run workflow」→ task は morning → 「Run workflow」を押します
5. 終わったら、その実行の画面の下の「Artifacts」から「試し運転の結果」をダウンロードします。中の md に、3本の案と、確かめの結果があります

メモリ（`メモリ/ネタ帳.md`・`メモリ/会社の事実.md`・`メモリ/テーマ.md`）は、最初は【見本】の架空の内容です。**見本のままでも試し運転は動きますが、本番の投稿は動きません**（見本の話を、そのまま投稿しないためです）。

<details>
<summary>手元のパソコンで試す場合</summary>

```
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...
PYTHONPATH=src python -m xjido morning --dry-run --no-x --no-github
```

テストは `python -m pytest -q` です。Claude のキーが無い時の開発用に、`--provider file`（依頼をファイルに書き出し、返事のファイルを読む）もあります。
</details>

## 費用の目安

<details>
<summary>X と Claude と GitHub の費用（開く）</summary>

どれも、使った分だけです。

**X（X API）**　出典：https://docs.x.com/x-api/getting-started/pricing（2026/11/26 に確認）

- 投稿する：1投稿 0.015ドル。1日 3本×3投稿＝9投稿で、月に約4ドル
- 自分の投稿を読む：1件 0.001ドル（自分の投稿の読み取り）〜0.005ドル（通常の投稿の読み取り）。朝に最大60件・週に最大200件で、月に約2〜9ドル

- 合計の目安は、**月に約6〜13ドル**です
- 自分の投稿を読む料金が、どちらの単価になるかは、X の使用状況の画面で確かめてください
- 投稿に URL を入れると、1投稿 0.200ドルになります。この仕組みは URL を入れない作りです（確かめで止めます）
- 同じ日に同じ投稿を読んでも、1回分です。最低の利用額はありません。料金は先払い（クレジットを買う）です
- 料金の画面に、月の使用額の上限を決める項目があれば、設定してください

**Claude（Anthropic API）**　料金表：https://www.anthropic.com/pricing 。初期の claude-sonnet-5-5 は、100万トークンあたり入力2ドル・出力10ドルです。1日に使う量は、入力が約2万トークン、出力が約5千トークンで、約0.09ドルです。確かめの AI の分を含めて、**月に約3〜6ドル**が目安です（2026/11/26 の料金で計算）。

**GitHub Actions**　非公開リポジトリは、無料の枠が月2,000分です。この仕組みは、投稿の時刻の前後だけ30分ごとに動くので、月に約750分です（枠の中です）。
</details>

## 設定の手順

<details>
<summary>X の API キーを取る（開く）</summary>

画面の名前は、X 側の更新で変わることがあります。違う時は、「〜のような項目」を探してください。

1. https://console.x.com を開き、投稿するアカウントでログインし、開発者の規約に同意します
2. 「New App」のような項目でアプリを作ります
3. アプリの設定で、「User authentication settings」のような項目を開き、**OAuth 1.0a を有効にします**
   - App permissions（アプリの権限）は **Read and Write**（読み書き）にします
   - Website URL は必須です。持っていなければ、このリポジトリの URL でかまいません
4. 「Keys and tokens」のような項目で、次の4つを作り、**その場でメモします**（もう一度は見られません）
   - API Key と API Key Secret
   - Access Token と Access Token Secret
5. **権限を Read and Write にしたあとに、Access Token を作ってください。** 権限を変える前に作った Access Token は、古い権限のままです。変えたあとは、Access Token を作り直します
6. 料金（クレジット）を買います。最初は10ドルで足ります

次に、GitHub の Secrets に、5つを入れます（「Settings」→「Secrets and variables」→「Actions」→「New repository secret」）。

| 名前 | 中身 |
|---|---|
| X_API_KEY | API Key |
| X_API_SECRET | API Key Secret |
| X_ACCESS_TOKEN | Access Token |
| X_ACCESS_TOKEN_SECRET | Access Token Secret |
| ANTHROPIC_API_KEY | Claude の API キー |
</details>

<details>
<summary>Workflow に書き込みの権限を渡す（開く）</summary>

「Settings」→「Actions」→「General」→ 一番下の「Workflow permissions」で、「Read and write permissions」を選んで保存します（記録の保存と、Issue の作成に使います）。
</details>

<details>
<summary>自分の事実を書く（開く）</summary>

次のファイルを、あなたの内容に直します（GitHub の画面で、ファイルを開いて、鉛筆のマークで直せます）。直したら、【見本】の文字を全部消します。

- `メモリ/会社の事実.md`：料金・エリア・定休日・件数など。数字は、ここに書いた物だけが、投稿で使えます
- `メモリ/ネタ帳.md`：現場の実話。ここに無い話は、「先日」「お客様から」と書けません
- `メモリ/お手本.md`：自分のアカウントで伸びたスレッドの全文。最初は架空の見本で、日曜の分析で自分の物に入れ替わります。最初から自分の物にしたい時は、伸びたスレッドを同じ形で貼ります
- `メモリ/テーマ.md`：書いてほしい話を1行ずつ（下の「テーマを入れる」）
- `メモリ/言い出し.md`：1つ目の最初の一言の候補（「覚えておいて」「断言します」など）。日曜の分析で、自分が使った言い出しが表示の多い順に入ります。直近の投稿と同じ言い出しの案は、投稿せずに捨てます
- `設定.yml`：アカウント名、投稿の時刻、確認の方式
</details>

## 本番にする

試し運転の案に、納得してからにしてください。**最初の1週間は、試し運転だけ**にして、メモリを直すのがおすすめです。

1. X の5つの Secrets を入れます（上の手順）
2. 「Actions」タブで、「1 朝の準備」「2 投稿」「3 週の分析」を、有効にします（最初は「有効にする」を押す画面が出ます）
3. 翌朝4時に、その日の3本が作られます。6時・12時・18時に投稿されます
4. 最初の1日は、投稿された内容を、X で見てください

## 止める

- 全部止める：「Actions」→ 左の一覧で止めたい物を選ぶ → 右上の「…」→「Disable workflow」
- 投稿だけ止める：「2 投稿」だけを Disable します（朝の準備は動き続け、予約がたまります）
- 今日の1本を出したくない：`data/予約.json` の、その物の「状態」を「捨てた」にします

## テーマを入れる

書いてほしい話を、1行書くだけです。毎朝4時に、上から順に、1テーマにつき1本のスレッドになります（テーマが無い日は、ネタ帳と会社の事実から選びます）。

- スマホから：GitHub アプリの「Issues」→ 新しい Issue。**題にテーマ**（例：「エコキュートの冬の凍結」）を書き、ラベル「テーマ」を付けます。本文は空でかまいません
- パソコンから：`メモリ/テーマ.md` の「まだ使っていないテーマ」に、`- エコキュートの冬の凍結` のように1行足します
- 実際にあったことや料金も使ってほしい時は、本文（ファイルなら「：」の後ろ）に書きます。例：「先週、室外機が雪で埋まって暖房が止まった家があった」。ここに書いた事実は、投稿に使えます

使ったテーマは、「使ったテーマ」に日付付きで移ります。

## 現場の話を足す

スマホの GitHub アプリで、リポジトリの「Issues」→ 新しい Issue を作ります。

1. 題は、一言（例：「水抜き栓が固着していた話」）
2. 本文に、実際に起きたことを書きます（いつ・どこ・何をしたか。数字があれば、そのまま）
3. ラベルは「ネタ」を付けます

翌朝4時に、`メモリ/ネタ帳.md` に入り、Issue は閉じられます。その話は、次の日から、「先日」「お客様から」と書く案に使えます。

## 確認待ちの見方

出どころを確かめられなかった案は、Issue（ラベル「確認待ち」）になり、投稿されません。

- 数字や話が本当なら、その Issue に、ラベル「OK」を付けます。次の投稿の時間に出ます
- 出したくないなら、その Issue を閉じます
- 数字が本当なら、ネタ帳か会社の事実に書き足すと、次から確認なしで通ります
- 足し算・割り算で作った数字（例：月150台÷30日）は止まります。元の数字と、計算した結果を、両方メモリに書いてください

### 確かめる物

- 数字（金額・件数・台数・年数・割合など）：メモリにあり、AI が出どころの文を一字も変えずに引用できた物だけ通ります
- 体験談の書き方（先日・最近・お客様から・ご依頼 など）：ネタ帳かテーマに出どころがある物だけ通ります
- 会社のやり方の書き方（うちでは・うちは・弊社では など）：メモリに出どころがある物だけ通ります
- 量の言い方（半年・倍・半分・ほとんど・全員・必ず など）：同じ言葉が出どころの文にある物だけ通ります
- URL、投稿の数、文字数の超過は、止まります
- 数字も体験談も使わない一般的な説明（仕組み・注意点・見方）は、確かめの対象外です。気になる時は、`設定.yml` の「確認: 方式」を「全部確認する」にしてください
- 最後の網として、別の AI（確認用のモデル）が、材料に無い具体的な主張が無いかを、もう一度見ます（`設定.yml` の「AIで二重に確かめる」。最初から有効です）

## 設定の意味（`設定.yml`）

<details>
<summary>項目の一覧（開く）</summary>

- **投稿: 時刻**：投稿する時刻（日本時間）。変えた時は、`.github/workflows/2-投稿.yml` の cron の時間も直します（ファイルの先頭に書いてあります）
- **投稿: スレッドの長さ**：1スレッドの投稿の数（初期は3）
- **投稿: 1投稿の最大文字数**：初期は280（日本語は全角140字まで）。X Premium に入っていれば、増やせます。1投稿の長さは、お手本の平均に合わせ、この上限より少し短く書きます
- **投稿: まとめるの最大_1日**：「まとめると」で締めるスレッドを、1日に何本までにするか（初期は1。お手本がいつも「まとめると」で締めているなら2に。3にすると、毎日全部が同じ締めになります）
- **確認: 方式**：次の3つから選びます
  - 「止まった時だけ確認」（初期）：止まった案だけ確認待ちにし、通った案は自動で予約します
  - 「全部確認する」：全部を確認待ちにして、OK を付けた物だけ出します
  - 「止まった案は捨てる」：止まった案は確認待ちにせず捨て、通った案だけ出します
- **確認: AIで二重に確かめる**：通った案を、別の AI にも見せます（初期は有効）
- **AI: モデル**：初期は claude-sonnet-5-5。claude-opus-5-5 / claude-haiku-5-5 にもできます（確認用のモデルも、初期は claude-sonnet-5-5）
</details>

## 注意

- **API キーは、誰にも渡さないでください。** Secrets 以外（Issue・チャット・ファイル）に書かないでください。漏れたら、すぐに作り直します
- X のルールを守ってください。同じ内容の連投や、自動の返信・フォローは、アカウントの制限につながります（この仕組みは、返信・フォロー・いいねをしません）。ルールは変わるので、X の最新の規約を見てください
- **最初は、必ず試し運転から始めてください**
- 投稿のあとで、事実の間違いに気づいたら、X で消してください（この仕組みは、投稿を消しません）
- 確かめは、メモリにある事実との照合です。メモリの内容が間違っていれば、間違った投稿も通ります
- 投稿に失敗した枠は、その日は止まり、「投稿の失敗」の Issue で知らせます（途中まで出た物は、続きから出し直します）
